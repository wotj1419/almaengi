# 개인화 노동법 RAG 챗봇 아키텍처 설계

> **작성일:** 2026.02.28
>
> **프로젝트:** 알바 근태 급여 관리 서비스 — 노동법 AI 챗봇
>
> **키워드:** Personalized RAG, Agentic RAG, Self-RAG, Hybrid Search, Semantic Router, 역할 기반 개인화

---

## 1. 개요

알바 근태 급여 관리 서비스에 노동법 AI 챗봇을 추가한다. 단순 법조문 검색이 아닌, **사장님/알바생 역할 + 매장 실제 데이터를 결합한 개인화 RAG 챗봇**을 구현한다.

**핵심 가치:**
- 소규모 자영업자가 노무사 상담(건당 3~5만원) 없이 노동법 궁금증을 해결
- 같은 질문이라도 **사장님에게는 의무/리스크**, **알바생에게는 권리/구제방법** 관점으로 답변
- 매장 실데이터(근태/급여)를 법령과 결합하여 **"김철수 알바생 주휴수당 36,108원"** 수준의 구체적 답변

## 2. 전체 시스템 아키텍처

AI 파이프라인은 Python 생태계(LangChain, 임베딩 모델, 벡터DB 클라이언트)가 압도적으로 유리하므로, **Spring Boot(비즈니스) + Python FastAPI(AI) 2개 서비스로 분리**한다.

```
[React 프론트엔드]
    │ SSE 스트리밍
    v
[Spring Boot 메인 백엔드]
    ├── 근태/급여/매장 비즈니스 API
    ├── 인증/인가 (JWT)
    ├── Chat Proxy Controller ──SSE/REST──→ [Python AI Service (FastAPI)]
    └── PostgreSQL                                 ├── Semantic Router (의도 분류)
         ├── 사용자/매장/근태/급여                   ├── Multi-Query (안전한 질문 확장)
         └── 대화 이력                              ├── RAG Pipeline (수동 그래프 검색)
                                                    ├── Agentic RAG (복합 질문)
                                                    ├── Self-RAG 검증 레이어
                                                    ├── Qdrant (벡터 DB)
                                                    └── Redis (캐시)
```

**서비스 간 통신 규격:**

| 항목 | 설계 |
| --- | --- |
| 프로토콜 | REST (동기) + SSE (스트리밍) |
| 인증 | 외부: JWT / 서비스 간: Internal API Key |
| 타임아웃 | 일반 10초 / 스트리밍 60초 / Agentic 30초 |
| Python→Spring Boot 호출 | `GET /api/internal/attendance/{storeId}/{employeeId}/weekly` 등 |

**요청 흐름 예시:**

```
사용자: "A 알바생 이번 달 주휴수당 얼마야?"

[React] → [Spring Boot] JWT 인증, 역할=OWNER 확인
    → [Python AI] Semantic Router → "복합질문" 판별
        → [Act 1] Spring Boot Internal API: A 알바생 주간 근무시간 조회 → 18시간
        → [Act 2] Qdrant 벡터DB: "주휴수당 계산 방법" 검색 → 근로기준법 제55조
        → [Self-RAG] 근거 충분성 검증
        → [Generate] OWNER 프롬프트로 답변 생성 (의무/리스크 관점)
    ← SSE 스트리밍으로 토큰 단위 응답
```

## 3. 핵심 기술 스택 선택 및 근거

| 컴포넌트 | 선택 | 선택 근거 |
| --- | --- | --- |
| **임베딩** | BGE-m3 (BAAI) | Dense + Sparse 벡터를 하나의 모델에서 동시 생성 → 별도 BM25 인덱스 불필요. 무료/로컬 배포. 한국어 벤치마크 상위 |
| **벡터 DB** | Qdrant | 네이티브 Hybrid Search + Payload Index 지원. 법명/조번호로 메타데이터 필터링하며 벡터 검색하는 복합 쿼리에 최적. Docker 1줄 배포 |
| **Reranker** | ms-marco-MiniLM-L-12 또는 Cohere Reranker | Cross-Encoder로 검색 정밀도 10~30% 향상. 추가 지연 ~50ms |
| **LLM** | GPT-4o-mini (70%) + GPT-4o (30%) | Semantic Router가 질문 복잡도를 판별하여 모델 라우팅 → 비용 70% 절감 |
| **프레임워크** | LangChain | Agent, Tool, Chain 오케스트레이션에 최적화된 생태계 |
| **캐시** | Redis | 응답 캐시 + 임베딩 캐시 + 세션 관리 |

## 4. RAG 파이프라인 상세

### 4.1 데이터 소스

| 소스 | 수량 추정 | 수집 방법 |
| --- | --- | --- |
| 근로기준법, 최저임금법, 고용보험법 등 | 5~6건 | 국가법령정보센터 Open API |
| 고용노동부 행정해석 | 200~500건 | 고용노동부 크롤링 |
| 주요 판례 | 50~100건 | 법제처 판례 DB |
| 고용노동부 FAQ | ~100건 | 크롤링 |

### 4.2 청킹 전략: 법률 문서 특화 구조 기반 + Parent-Child

법률 문서의 `편 > 장 > 절 > 조 > 항 > 호 > 목` 계층 구조를 활용한다.

```
검색 단위 (Child Chunk): 조/항 단위 (100~500자) → 정밀한 벡터 매칭
LLM 전달 단위 (Parent Chunk): 조 전체 + 관련 행정해석 → 풍부한 문맥 제공

예시:
[Child - 검색용] 제55조 제1항
  "사용자는 1주에 평균 1회 이상의 유급휴일을 보장하여야 한다."
  metadata: {법명: "근로기준법", 조: 55, 항: 1, 키워드: ["주휴일","유급휴일"]}

[Parent - LLM 전달용] 제55조 전체 + 관련 행정해석 2024-1234
```

| 문서 유형 | 청킹 단위 | 평균 크기 |
| --- | --- | --- |
| 법률 조문 | 조/항 단위 | 100~500자 |
| 행정해석 | 질의+회시 쌍 | 300~800자 |
| 판례 | 판시사항/이유 분리 | 500~1000자 |
| FAQ | Q+A 쌍 | 200~500자 |

### 4.3 검색 파이프라인 (5단계)

```
[Stage 1] 질문 임베딩
  BGE-m3 → Dense 벡터 + Sparse 벡터 동시 생성

[Stage 2] Hybrid Search (Qdrant)
  Dense Search: 의미적 유사 문서 ("주휴수당 지급 조건" 등)
  Sparse Search: 키워드 매칭 ("15시간", "제55조" 등)
  RRF (Reciprocal Rank Fusion)로 결합 → Top-20

[Stage 3] 메타데이터 필터링
  법령 문서 우선, 최신 개정 우선

[Stage 4] Reranking (Cross-Encoder)
  Top-20 → Top-5 재순위. 질문-문서 쌍을 직접 비교

[Stage 5] Parent Chunk 확장
  Top-5 Child의 Parent Chunk + 관련 행정해석 로드
  → 최종 Context: 5~8개 문서 (2000~4000 토큰)
```

### 4.4 HyDE (Hypothetical Document Embeddings)

질문을 바로 검색하는 대신, LLM이 가상 답변을 먼저 생성하고 그 답변을 임베딩하여 검색한다. 답변과 유사한 문서를 더 정확하게 찾을 수 있어 Context Recall이 약 10~15% 향상된다.

```
원본 질문: "주 15시간 미만 알바도 주휴수당 받을 수 있나요?"

LLM 가상 답변 (검색용):
"근로기준법 제18조에 따르면 1주 동안의 소정근로시간이 15시간 미만인
근로자에 대하여는 제55조의 유급휴일 규정을 적용하지 아니한다."

→ 이 가상 답변을 임베딩하여 벡터DB 검색 → 더 정확한 문서 검색
```

## 5. 개인화 전략 (핵심 차별점)

### 5.1 Semantic Router — 질문 의도 자동 분류

임베딩 유사도 기반으로 **10ms 이내에 분류** (LLM 호출 불필요, 비용 0):

```
사용자 질문
    ↓
[Semantic Router - 임베딩 유사도 기반]
    │
    ├─ LEGAL_QUERY ("주휴수당 조건이 뭐야?")
    │   → RAG Pipeline (Qdrant 벡터DB 검색)
    │
    ├─ DATA_QUERY ("A 알바생 이번 달 근무시간?")
    │   → DB Query Agent (Spring Boot Internal API 호출)
    │
    ├─ COMPLEX_QUERY ("A 알바생 4대보험 가입해야 해?")
    │   → Agentic RAG (DB + 벡터DB 결합, 멀티스텝 추론)
    │
    ├─ CALCULATION ("시급 10,030원 주 20시간이면 월급?")
    │   → Calculator Agent + RAG (계산식 + 법적 근거)
    │
    └─ GENERAL ("안녕하세요")
        → Direct LLM (검색 불필요, GPT-4o-mini로 즉시 응답)
```

**구현 방식:** `semantic-router` 라이브러리 활용. 의도별 30~50개 예시 문장의 임베딩과 사용자 질문 임베딩의 유사도를 비교하여 분류한다.

### 5.2 역할 기반 프롬프트 — 같은 질문, 다른 관점의 답변

**사장님(OWNER) 프롬프트:**
- 사업주의 법적 **의무와 리스크** 관점
- 미이행 시 **과태료/벌금** 정보 함께 안내
- "~하셔야 합니다", "~할 의무가 있습니다" 어투
- 실무 적용 팁 (급여명세서 기재 방법 등)

**알바생(WORKER) 프롬프트:**
- 근로자의 **권리 보호** 관점
- 권리 침해 시 **구제 방법** (노동청 신고 등) 안내
- "~받을 권리가 있습니다", "~요청할 수 있습니다" 어투
- 어려운 법률 용어는 쉬운 말로 풀어서 설명

**답변 비교 예시 — "주휴수당이 뭔가요?":**

| 사장님에게 | 알바생에게 |
| --- | --- |
| 주휴수당은 근로기준법 제55조에 따라 1주 소정근로일을 개근한 근로자에게 유급휴일을 부여해야 하는 **의무**입니다. | 주휴수당은 쉽게 말해 **'일주일 동안 빠지지 않고 출근하면 받는 보너스'**예요! |
| **미지급 시** 임금체불에 해당하며, 3년 이하 징역 또는 3천만원 이하 벌금 (근로기준법 제109조) | 만약 사장님이 **안 주시면** 노동청(1350)에 신고할 수 있어요 |
| 급여명세서에 '주휴수당' 항목을 **별도 기재**하세요 (제48조 임금명세서 교부 의무) | 시급과 별도로 **추가 지급**되는 거예요 (시급에 포함 X) |

### 5.3 Agentic RAG — 매장 실데이터 + 법령 결합

복합 질문에 대해 에이전트가 **Plan → Act → Observe → Reflect** 루프를 수행한다.

```
질문: "우리 매장 알바생 중에 4대보험 가입해야 하는 사람이 누구야?" (OWNER)

[Plan] 이 질문에 답하려면:
       (1) 매장 전체 직원 목록과 근무시간 조회
       (2) 4대보험 가입 기준 법령 검색
       (3) 각 직원별 기준 충족 여부 판단

[Act 1] get_store_summary(store_123) → Spring Boot API 호출
  결과: 김철수(22h/주), 이영희(12h/주), 박민수(35h/주)

[Act 2] search_labor_law("4대보험 가입 의무 조건") → Qdrant 검색
  결과: 국민연금법 시행령 - 월 60시간 이상, 고용보험법 - 주 15시간 이상

[Observe]
  김철수: 주 22시간 (월 ~95시간) → 전 항목 가입 대상
  이영희: 주 12시간 (월 ~52시간) → 미가입 대상
  박민수: 주 35시간 (월 ~152시간) → 전 항목 가입 대상

[Reflect]
  이영희는 현재 미가입이지만 주 3시간만 추가되면 기준 초과 → 안내 필요

[Generate]
  "현재 매장 알바생 3명의 4대보험 가입 의무 현황입니다:

   | 이름    | 주간 근무 | 월간 추정 | 가입 대상 |
   |---------|-----------|-----------|-----------|
   | 김철수  | 22시간    | 95시간    | O (전 항목) |
   | 이영희  | 12시간    | 52시간    | X         |
   | 박민수  | 35시간    | 152시간   | O (전 항목) |

   근거: 국민연금법 시행령 제2조, 고용보험법 시행령 ...

   ⚠️ 이영희 알바생은 주 3시간 추가 시 월 60시간을 초과하여
   가입 의무가 발생합니다. 근무 스케줄 조정 시 유의해주세요."
```

**Agentic RAG 사용 가능 도구(Tools):**

| 도구 | 기능 | 호출 대상 |
| --- | --- | --- |
| `search_labor_law(query)` | 벡터DB 노동법 문서 검색 | Qdrant |
| `get_employee_attendance(storeId, empId, period)` | 근태 데이터 조회 | Spring Boot API |
| `get_employee_info(storeId, empId)` | 직원 정보 (시급, 입사일 등) | Spring Boot API |
| `get_store_summary(storeId)` | 매장 전체 인력 현황 | Spring Boot API |
| `calculate(expression)` | 수식 계산 (주휴수당, 퇴직금 등) | 로컬 |

### 5.4 Self-RAG 검증 — 법률 AI 환각 방지

법률 AI에서 환각(hallucination)은 실질적 피해로 이어지므로, 4단계 자기 검증을 적용한다.

| 검증 토큰 | 역할 | 예시 |
| --- | --- | --- |
| **Retrieve?** | 검색이 필요한 질문인지 판단 | "안녕하세요" → 검색 불필요 → 비용 절감 |
| **IsRelevant?** | 검색된 문서가 질문에 관련 있는지 | "이 문서는 주휴수당이 아니라 연차 내용 → 제외" |
| **IsSupported?** | 답변이 검색 문서에 의해 뒷받침되는지 | "이 답변의 근거가 검색 문서에 있는가?" |
| **IsUseful?** | 최종 답변이 사용자에게 유용한지 | "질문에 충분히 답했는가?" |

근거가 불충분한 경우: "정확한 답변을 위해 고용노동부(1350)에 문의하시기를 권합니다."

## 6. 성능 최적화 전략

### 6.1 정확도 최적화 — 기법별 개선 효과

| 기법 | 개선 지표 | 예상 효과 | 우선순위 |
| --- | --- | --- | --- |
| Hybrid Search (Dense+Sparse) | Context Recall | +15~20% | **P0 필수** |
| Reranking (Cross-Encoder) | Context Precision | +10~30% | **P0 필수** |
| 구조 기반 청킹 (조/항 단위) | Context Precision | +10~15% | **P0 필수** |
| Parent-Child 청킹 | Faithfulness | +5~10% | P1 권장 |
| Self-RAG 검증 | Hallucination Rate | **-20~40%** | P1 권장 |
| HyDE | Context Recall | +10~15% | P2 선택 |
| Agentic RAG | Answer Relevancy | +15~25% (복합질문) | P1 핵심 차별점 |
| Semantic Router | Answer Relevancy | +10% (오분류 방지) | **P0 필수** |

### 6.2 속도 최적화

| 기법 | 효과 |
| --- | --- |
| **SSE 스트리밍** | 첫 토큰 출력 < 1초 (전체 응답 대기 불필요) |
| **Redis 응답 캐시** | 반복 질문 시 < 50ms (질문 임베딩 해시 기반 캐시 키, TTL 24시간) |
| **임베딩 캐시** | ~100ms 절감 (자주 묻는 질문 패턴 사전 캐싱) |
| **비동기 처리** | 동시 100+ 요청 (FastAPI async + asyncio.gather 병렬 검색) |

## 7. 점진적 개발 로드맵 + RAGAS 평가

```
Phase 1 (MVP, 2주)
  기본 RAG + 구조 기반 청킹 + Hybrid Search
  → RAGAS Baseline 확보

Phase 2 (고도화 1, 1주)
  + Reranking + Parent-Child + 역할 기반 프롬프트
  → 정밀도 향상 측정 (Phase 1 대비)

Phase 3 (고도화 2, 2주)
  + Semantic Router + Agentic RAG + Self-RAG
  → 개인화 + 정확도 최종 향상

Phase 4 (최적화, 1주)
  + HyDE + Redis 캐싱 + SSE 스트리밍 최적화
  → 속도 + 비용 최적화
```

| 지표 | Phase 1 (기본) | Phase 2 (+개인화) | Phase 3 (+Agent) |

| Answer Relevancy | >= 0.70 | >= 0.80 | >= 0.90 |

**평가 데이터셋:** 법령 질문 50건 + 매장 데이터 질문 30건 + 복합 질문 20건 (총 100건, 각각에 정답 + 관련 문서 수작업 라벨링)

## 9. 기술 면접 어필 포인트

| 예상 질문 | 어필 포인트 |
| --- | --- |
| "왜 BGE-m3를 선택했나요?" | Dense + Sparse 벡터를 하나의 모델에서 동시 생성 → 별도 BM25 인덱스 불필요. 법률 조문 번호(Sparse 매칭)와 법적 개념(Dense 매칭)을 동시에 커버 |
| "ChromaDB 대신 Qdrant를 선택한 이유는?" | ChromaDB는 Dense 검색만 지원하지만, Qdrant는 네이티브 Hybrid Search + Payload Index 지원. 법명/조번호로 메타데이터 필터링하면서 벡터 검색하는 복합 쿼리가 핵심이었기 때문 |
| "Self-RAG는 왜 적용했나요?" | 법률 AI에서 환각은 실질적 피해로 이어짐. IsSupported 검증으로 Hallucination Rate를 15%에서 3%로 낮추는 것이 목표 |
| "비용은 얼마나 드나요?" | Semantic Router로 70% 질문을 GPT-4o-mini로 라우팅 + Redis 캐시. 월 약 54만원으로 1000명 사용자 서빙 (전체 GPT-4o 사용 대비 70% 절감) |
| "개인화는 어떻게 구현했나요?" | 역할별 시스템 프롬프트 분리 + Agentic RAG가 매장 실데이터(근태/급여 DB)와 비정형 지식(노동법)을 자율적으로 결합. "김철수 알바생 주휴수당 36,108원" 수준의 구체적 답변 |
| "성능은 어떻게 측정하나요?" | RAGAS 프레임워크로 Context Precision, Faithfulness, Hallucination Rate 자동 측정. 100건 평가 데이터셋을 구축하고 Phase별 A/B 비교로 각 기법의 기여도를 정량적으로 분리 |

## 고민 중인 내용

### Multi-Query Retrieval (질문 확장) — HyDE 대안

환각 위험이 있는 가상 답변 생성(HyDE) 대신, 질문을 다각도로 재작성하여 검색 재현율을 높이는 **Multi-Query** 방식을 채택한다.

* **동작 방식:** LLM에게 "조항 번호는 추측하지 말고 검색을 위한 다양한 키워드나 질문을 3개 생성해달라"고 지시한다.
* **장점:** 특정 조항 번호에 대한 환각 위험이 없으며, "15시간" 같은 핵심 키워드가 포함된 여러 쿼리로 검색하여 정확한 문서를 찾을 확률을 높인다.

### 하이브리드 검색 및 리랭킹 (5단계)

1. **질문 임베딩:** BGE-m3로 Dense/Sparse 벡터 생성
2. **Hybrid Search:** 의미(Dense) + 키워드(Sparse) 검색 결합
3. **메타데이터 필터링:** 법령/최신성 우선순위 적용
4. **Reranking:** 상위 후보군 재순위 산정
5. **Context 확장:** 검색된 Child의 Parent Chunk 및 연관 정보 로드

### 메타데이터 기반 수동 지식 그래프 (Manual GraphRAG) <- 개인화 및 고도화 전략에 추가

노동법은 엔티티 관계가 명확하고 문서량이 적으므로, Qdrant 메타데이터를 활용한 **수동 그래프 순회**를 구현한다.

**Qdrant Payload 구조 예시:**

```json
{
  "content": "근로기준법 제55조(휴일)...",
  "metadata": {
    "law_name": "근로기준법",
    "article": 55,
    "related_articles": ["제18조", "제109조"],
    "concepts": ["주휴수당", "4대보험"],
    "target": "주 15시간 이상 근로자"
  }
}

```

* **검색 로직:** 1차 검색으로 제55조가 검색되면, 메타데이터의 `related_articles`를 읽어 제18조(단시간 근로자)를 자동으로 함께 로드한다. 이는 LLM의 추측이 아닌 검증된 데이터 기반 연결이므로 환각이 없다.
