## 1. 프로젝트 개요

### 1.1 배경 및 문제 정의

해외여행에 대한 수요는 꾸준히 증가하고 있으며, 특히 친구·연인·가족 단위의 그룹 여행이 보편화되고 있다. 그러나 그룹 여행을 계획할 때 다음과 같은 문제가 반복적으로 발생한다.

| 구분 | 문제 |
| --- | --- |
| 문제 1 | 해외여행 경험이 적으면 어떤 나라에 얼마가 드는지 감이 없음 — 여행지별 비용을 알아보는 데 서칭 시간과 에너지가 과도하게 소모됨|
| 문제 2 | "예산은 얼마가 있는 거지?"부터 막힘 — 그룹 구성원 각각의 자금 상황을 파악하기 어려움  |
| 문제 3 | 예산에 맞는 여행지를 찾기 위해 여러 플랫폼을 번갈아가며 항공권·숙박·현지 경비를 각각 비교해야 함 |

기존 서비스들은 공금 모으기(토스, 카카오페이), 항공권·숙박 검색(스카이스캐너, 여기어때), 환전(트래블월렛) 등 개별 기능을 제공하지만, **"우리가 가진 돈과 앞으로 모을 돈으로 어디까지 여행을 갈 수 있는지"를 보여주는 서비스는 부재**한 상황이다.

### 1.2 서비스 비전

FarFund는 그룹의 현재 자산과 미래 저축 가용액을 분석하여, <b>실시간으로 '갈 수 있는 여행'과 '갈 수 있게 될 여행'을 제안하는 여행 자금 플래너이다.</b>

저축 금액이 변하면 추천 선택지가 실시간으로 업데이트되어, 별도의 동기부여 장치 없이도 **저축 자체가 동기부여가 되는 구조**를 만든다.

> **서비스명 'FarFund'에 대하여:** '더 멀리(Far) 갈 수 있게 해주는 자금(Fund)'이라는 의미를 담았다. 저축할수록 더 먼 곳, 더 나은 여행이 가능해지는 서비스의 핵심 경험을 네이밍에 반영했다. (가제 — 최종 네이밍은 팀 논의 후 확정)

### 1.3 핵심 가치 제안 (Value Proposition)

| 구분 | 기존 여행 서비스 | FarFund |
| --- | --- | --- |
| 시작점 | 예산을 정하고 → 여행을 검색 | 자금을 입력하면 → 여행이 추천됨 |
| 추천 방식 | 사용자가 직접 검색·비교 | 예산 구간별 자동 매칭 |
| 저축 연동 | 없음 (별도 앱에서 관리) | 저축 금액 변경 → 선택지 실시간 변화 |
| 그룹 지원 | 공금 모으기만 제공 | 그룹 자금 현황 + 여행 추천 통합 |
| 핵심 경험 | 검색 → 비교 → 결정 | 저축 → 선택지 확장 → 결정 |

### 1.4 대상 사용자

해외 여행을 계획하는 그룹 (친구, 연인, 가족 등)

| 세그먼트 | 특성 | 핵심 니즈 |
| --- | --- | --- |
| 대학생 그룹 | 예산 제한적, 시간 여유 있음 | 적은 예산으로 갈 수 있는 최적 여행지 탐색 |
| 직장인 친구 그룹 | 각자 저축 여력 다름, 일정 조율 필요 | 그룹 예산 통합 관리 + 빠른 의사결정 |
| 커플 | 기념일 등 목표 날짜 있음 | 목표일까지 저축하면 갈 수 있는 여행 확인 |
| 가족 | 비교적 예산 여유, 패키지 선호 | 인원 수 기반 총 비용 산출 + 패키지 비교 |

## 2. 핵심 기능 상세 (MVP)

### 2.1 그룹 자금 대시보드

그룹원 각각의 현재 자산과 월/일 저축 가능 금액을 입력하면, 전체 그룹 예산을 자동 산출한다.

#### 2.1.1 수집 정보

| 항목 | 입력 방식 | 활용 목적 |
| --- | --- | --- |
| 그룹 인원 | 그룹 생성 시 초대 | 1인당 비용 산출 기준 |
| 개인별 현재 자산 | 직접 입력 (여행 자금으로 활용 가능한 금액) | 현재 가용 예산 산출 |
| 월/일 저축 금액 | 직접 입력 (슬라이더 또는 직접 입력) | 미래 예산 예측 |
| 희망 출발 시기 | 날짜 선택 | 저축 기간 계산 → 출발일까지 예상 총 예산 산출 |
| 선호 여행 권역 | 선택 (동남아/동아시아/유럽/아메리카/오세아니아 등) | 추천 여행지 범위 제한 → 예산 매칭 정확도 향상 |

#### 2.1.2 산출 결과

| 항목 | 계산 방식 |
| --- | --- |
| 현재 총 예산 | 그룹원 현재 자산의 합계 |
| 출발일 기준 예상 총 예산 | 현재 총 예산 + (각 그룹원 월 저축액 × 남은 개월 수)의 합계 |
| 1인당 평균 예산 | 예상 총 예산 ÷ 그룹 인원 수 |

---

### 2.2 예산 기반 여행 추천

산출된 예산을 기반으로 두 가지 카테고리로 여행 선택지를 제안한다. 이것이 서비스의 핵심 경험이다.

#### 2.2.1 추천 카테고리

| 카테고리 | 조건 | 표시 정보 | 핵심 경험 |
| --- | --- | --- | --- |
| 🟢 지금 갈 수 있는 여행 | 현재 자산으로 바로 가능 | 여행지, 항공권+숙박 예상 비용, 예상 현지 경비 | 즉시 예약 유도 |
| 🔵 갈 수 있게 될 여행 | 출발일까지 저축 완료 시 가능 | 여행지, 예상 비용, 필요 저축 기간, 월 저축액 가이드 | 저축 동기부여 |

#### 2.2.2 저축 동기부여 UX

**'갈 수 있게 될 여행'** 카테고리에서는 저축 금액 변경에 따른 선택지 변화를 직관적으로 보여준다. 예를 들어:

- "현재 저축 계획대로면 오사카 여행이 가능해요!"
- "월 5만원씩만 더 모으면 발리도 갈 수 있어요! 🌴"

저축 금액 슬라이더를 조절하면 추천 여행지가 실시간으로 바뀌는 것이 서비스의 '아하 모먼트(Aha Moment)'이다.

#### 2.2.3 여행 비용 산출 기준

MVP에서는 패키지여행 또는 자유여행(항공권 + 숙박 개별 조합)을 우선 지원한다.

| 비용 항목 | 데이터 소스 | 산출 방식 |
| --- | --- | --- |
| 항공권 | Amadeus API | 출발일 기준 최저가~평균가 범위 |
| 숙박 | Amadeus API | 인원·박수 기준 평균 숙박비 |
| 현지 경비 | 자체 데이터 (국가별 일 평균 경비) | 1인 1일 평균 식비+교통+관광 추정치 |
| 총 예상 비용 | 항공권 + 숙박 + (현지 경비 × 일수 × 인원) | 최소~최대 범위로 표시 |

> **패키지 여행 추천:** 현재 패키지 가격 데이터 소싱 방안을 검토 중이며 (제휴 또는 크롤링), 확보 가능 시 MVP로 선택할 예정이다.

---

### 2.3 특가 알림

목표 여행지의 항공권·숙박 가격이 설정한 목표가 이하로 떨어지거나 최저가가 갱신되면 푸시 알림을 발송한다. 이미 예매한 상태여도 취소 수수료까지 계산했을 때 더 저렴하다면 알림을 발송한다.

| 항목 | 내용 |
| --- | --- |
| 알림 조건 | 목표가 이하 도달 또는 최저가 갱신|
| 알림 대상 | 그룹원 전원 동시 발송 |
| 알림 내용 | 여행지, 현재 가격, 목표가 대비 할인율 |
| 목적 | 빠른 그룹 의사결정 유도 |

## 3. 사용자 여정 (User Flow)

### 3.1 전체 사용자 여정

| 단계 | 화면 | 사용자 행동 | 시스템 반응 |
| --- | --- | --- | --- |
| Step 1 | 그룹 생성 | 그룹을 만들고 구성원을 초대 | 그룹 공간 생성 + 초대 링크 발송 |
| Step 2 | 자금 입력 | 각자 현재 자산, 월/일 저축 가능 금액, 희망 출발 시기, 선호 권역 입력 | 그룹 총 예산 자동 산출 |
| Step 3 | 🔍 탐색 — 추천 확인 | '지금 가능' / '곧 가능' 여행 선택지 확인 및 비교 | 예산 기반 여행지 추천 리스트 표시 (항공권+숙박 합산) |
| Step 4 | 🔍 탐색 — 저축 조정 | 저축 금액 슬라이더 조절하며 선택지 변화 확인 | 추천 선택지 실시간 업데이트 |
| Step 5 | ✅ 확정 — 여행지 확정 | 그룹이 여행지를 확정하고 특가 알림 설정 | 확정 여행지 기준 항공권·숙박 가격 모니터링 시작 |
| Step 6 | ✅ 확정 — 예매 | 특가 알림 수신 후 예매 결정 | 항공권·숙박 예약 페이지로 연결 (외부 링크) |

### 3.2 탐색 단계 vs 확정 단계

서비스의 핵심 구조는 **탐색 단계와 확정 단계의 분리**에 있다.

**탐색 단계 (Step 2~4):** 저축하면서 가능한 여행지를 구경하는 단계. 예산이 바뀌면 추천도 바뀌지만, 아직 예매를 하지 않았으므로 자유롭게 탐색할 수 있다. 이 단계에서 "저축할수록 선택지가 늘어나는" 핵심 경험이 발생한다.

**확정 단계 (Step 5~6):** 그룹이 여행지를 확정하고 실제 예매를 준비하는 단계. 특가 알림이 예매 타이밍을 잡아주는 역할을 한다.

### 3.3 핵심 루프

서비스의 핵심 사용 루프는 다음과 같다:

**저축 금액 입력/변경 → 추천 선택지 실시간 업데이트 → 더 나은 선택지 발견 → 저축 동기 강화 → 저축 금액 상향**

이 루프가 자연스럽게 반복되도록 하는 것이 서비스 설계의 핵심이다.

## 4. 기술 스택 및 API

### 4.1 외부 API

| API | 용도 | 비고 |
| --- | --- | --- |
| Amadeus API | 항공권 검색 및 가격 조회 | 무료 티어 제공 (월 요청 수 제한 있음), 항공권 최저가·평균가 조회 가능 |
| Booking.com Affiliate API | 숙박 검색 및 가격 조회 | 어필리에이트 프로그램 통해 접근, 숙박 시설 검색·가격·리뷰 조회 가능 |
| 금융 API | 계좌 조회, 이체, 환전 등 | 제공받는 API 활용 (상세 지원 범위 확인 필요) |

### 4.2 금융 API 확인 필요 사항

금융 API의 지원 범위에 따라 서비스 기능 범위가 달라지므로, 다음 항목을 우선 확인해야 한다:

| 확인 항목 | 영향 범위 | 대안 (미지원 시) |
| --- | --- | --- |
| 공금 통장 개설 가능 여부 | 그룹 자금 통합 관리 기능 | 각자 개별 저축 → 금액만 입력 방식으로 대체 |
| 자동 이체/저축 설정 기능 | 저축 자동화 | 수동 입력 + 리마인더 알림으로 대체 |
| 공금에서 직접 결제/이체 | 여행 중 공금 결제 (2차 기능) | 외부 결제 수단 연결로 대체 |
| 환전 기능 | 공금 통장 환전 (2차 기능) | 외부 환전 서비스 연결로 대체 |

### 4.3 기술 스택 (안)

> 팀 역량과 선호에 따라 조정 필요 — 논의 후 확정

| 영역 | 후보 기술 | 선정 사유 |
| --- | --- | --- |
| 프론트엔드 | React Native 또는 Flutter | iOS/Android 동시 개발, 빠른 프로토타이핑 |
| 백엔드 | Spring Boot 또는 FastAPI | 금융 API 연동 안정성, 팀 기술 스택에 따라 결정 |
| DB | PostgreSQL | 사용자 데이터, 그룹 정보, 저축 이력 저장 |
| 캐시 | Redis | 항공권·숙박 가격 데이터 캐싱 (API 호출 최소화) |
| 인프라 | AWS 또는 GCP | 확장성, 관리형 서비스 활용 |

## 5. 개발 로드맵

### 5.1 단계별 개발 계획

| 단계 | 범위 | 주요 개발 항목 | 마일스톤 |
| --- | --- | --- | --- |
| **1차: MVP** | 저축 + 추천 | 그룹 생성 및 자금 입력, 예산 기반 여행 추천, 저축 금액 변경 시 실시간 선택지 업데이트, 항공권·숙박 특가 알림 | 내부 테스트 |
| **2차: 여행 실행 지원** | 관리 + 결제 | 공금 통장 개설 및 결제/이체, 환전 기능, 여행 중 가계부 (일별/카테고리별 지출 조회), 패키지 여행 추천 추가 (제휴 기반) | 클로즈드 베타 |
| **3차: 고도화** | 개인화 + 확장 | 여행 취향 기반 개인화 추천, 여행 후기/리뷰 연동, 반복 사용자 리텐션 기능 | 정식 출시 |

## 6. 경쟁 서비스 분석

### 6.1 기능별 비교

| 기능 | FarFund | 토스 | 카카오페이 | 트래블월렛 | 스카이스캐너 |
| --- | --- | --- | --- | --- | --- |
| 그룹 저축 | ● | ● | ● | ○ | ○ |
| 예산 → 여행 추천 | **●** | ○ | ○ | ○ | ○ |
| 실시간 선택지 변화 | **●** | ○ | ○ | ○ | ○ |
| 항공권·숙박 검색 | ● | ○ | ○ | ○ | ● |
| 환전 | 2차 | ● | ○ | ● | ○ |
| 여행 중 결제 | 2차 | ● | ● | ● | ○ |

> ● = 지원 | ○ = 미지원

### 6.2 FarFund의 차별화 포인트

기존 서비스들이 여행의 **개별 단계**(저축, 검색, 환전, 결제)를 각각 해결하는 반면, FarFund는 <b>'저축에 따라 여행 선택지가 변화하는 경험'</b>이라는 고유한 가치를 제공한다. 이 경험은 다른 서비스에서 조합으로도 재현하기 어렵다.

## 7. 리스크 및 대응 방안

| 구분 | 리스크 | 영향도 | 대응 방안 |
| --- | --- | --- | --- |
