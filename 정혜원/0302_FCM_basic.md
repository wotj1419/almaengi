## 1. FCM의 정의 및 특징

* **정의:** 구글에서 제공하는 **무료** 교차 플랫폼(Android, iOS, Web) 메시징 솔루션.
* **주요 역할:** 서버에서 앱으로 알림(Push)이나 데이터를 보낼 때 중간 다리 역할을 수행.
* **특징:**
* **배터리 효율:** 기기가 서버와 항상 연결되어 있지 않아도 FCM이 대신 연결을 유지하다가 메시지를 전달함.
* **비용 제로:** 메시지 전송량에 제한이 없으며 전면 무료.
* **타겟팅:** 특정 기기, 기기 그룹, 혹은 특정 주제(Topic)를 구독한 사용자에게 발송 가능.

---

## 2. FCM 동작 아키텍처

FCM은 단순히 '보내는 것'이 아니라, **서버 - FCM 서버 - 기기**가 엮여서 동작.

1. **토큰 발행:** 앱이 설치되면 FCM 서버로부터 고유한 **Registration Token**을 발급받음.
2. **토큰 저장:** 앱은 이 토큰을 나의 **자체 서버(App Server)** 에 전달하여 DB에 저장함.
3. **메시지 요청:** 내 서버에서 특정 사용자에게 알림을 보낼 때, 저장된 토큰과 메시지 내용을 담아 **FCM 서버로 전송 요청**을 보냄.
4. **메시지 전달:** FCM 서버가 해당 토큰을 가진 기기를 찾아 메시지를 최종 전달.

---

## 3. 메시지 유형

FCM 메시지는 크게 두 가지로 나뉨. 어떤 것을 쓰느냐에 따라 앱의 동작이 달라진다.

| 유형 | 알림 메시지 (Notification) | 데이터 메시지 (Data) |
| --- | --- | --- |
| **구성** | `title`, `body` 등 정해진 키 사용 | 개발자가 정의한 커스텀 키-값 쌍 |
| **백그라운드 동작** | 시스템 트레이에 자동으로 알림 표시 | 앱의 `onMessageReceived`에서 직접 처리 |
| **특징** | 구현이 매우 간단함 | 앱이 꺼져 있어도 로직 처리가 필요할 때 사용 |
| **사용 사례** | 단순 공지, 마케팅 알림 | 채팅 메시지, 조용히 데이터 동기화 |

## 4. 핵심 기능 개념

### 🔹 Registration Token

* 각 기기의 앱 인스턴스를 식별하는 **고유 주소**.
* 앱 업데이트, 재설치, 데이터 삭제 시 토큰이 갱신될 수 있으므로 서버는 항상 최신 토큰을 유지해야 함.

### 🔹 Topic Messaging (발행/구독)

* 특정 주제(예: '날씨', '공지사항')를 구독한 모든 기기에 메시지를 한 번에 뿌리는 방식.
* 개별 토큰을 관리할 필요가 없어 대규모 공지에 유리함.

### 🔹 Foreground vs Background 처리

* **Foreground (앱 실행 중):** 메시지가 오면 무조건 코드에서 직접 처리해야 함.
* **Background (앱이 뒤에 있거나 꺼짐):** 알림 메시지는 시스템이 대신 띄워주고, 데이터 메시지는 코드 내 핸들러가 호출됨.
