# FCM 발송 back 로직

## 1. 사전 준비 (Prerequisites)

* **Firebase Console 설정:** 프로젝트 설정 > 서비스 계정 > **새 비공개 키 생성**을 통해 `.json` 키 파일을 다운로드.
* **의존성 추가 (Gradle):**
```gradle
implementation 'com.google.firebase:firebase-admin:9.2.0'

```



---

## 2. FCM 초기화 (Initialization)

서버 기동 시 한 번만 실행되도록 설정 클래스(`@Configuration`)로 구현.

* **핵심 포인트:** 다운로드한 JSON 키 파일을 읽어 `FirebaseApp`을 초기화.
* **코드 예시:**
```java
@Configuration
public class FcmConfig {
    @PostConstruct
    public void init() throws IOException {
        FileInputStream serviceAccount = new FileInputStream("src/main/resources/serviceAccountKey.json");
        FirebaseOptions options = FirebaseOptions.builder()
                .setCredentials(GoogleCredentials.fromStream(serviceAccount))
                .build();
        FirebaseApp.initializeApp(options);
    }
}

```



---

## 3. 메시지 발송 로직 (Core Logic)

FCM 서버로 메시지를 보내는 핵심 코드. `FirebaseMessaging` 객체를 사용.

### 🔹 단일 기기 발송 (Single Device)

특정 사용자의 토큰을 사용하여 1대 1로 발송.

```java
public void sendToToken(String token, String title, String body) throws FirebaseMessagingException {
    // 1. 메시지 구성 (Notification + Data)
    Message message = Message.builder()
            .setToken(token) // 수신자 토큰
            .setNotification(Notification.builder()
                    .setTitle(title)
                    .setBody(body)
                    .build())
            .putData("click_action", "OPEN_EVENT_PAGE") // 커스텀 데이터
            .build();

    // 2. 발송
    String response = FirebaseMessaging.getInstance().send(message);
    System.out.println("Successfully sent message: " + response);
}

```

### 🔹 다중 기기 발송 (Multicast)

여러 명에게 동시에 보낼 때 효율적. (최대 500개까지 권장)

```java
public void sendMulticast(List<String> tokens) throws FirebaseMessagingException {
    MulticastMessage message = MulticastMessage.builder()
            .addAllTokens(tokens)
            .setNotification(Notification.builder().setTitle("공지").setBody("내용").build())
            .build();

    BatchResponse response = FirebaseMessaging.getInstance().sendEachForMulticast(message);
    System.out.println(response.getSuccessCount() + " messages were sent successfully");
}

```

## 4. 메시지 발송 프로세스 구조

1. **Java App:** 비즈니스 로직에서 발송 조건 발생.
2. **Admin SDK:** `Message` 객체를 빌드하고 FCM 백엔드로 HTTPS 요청 전송.
3. **FCM Backend:** 요청을 검증하고 타겟 기기(토큰)를 확인.
4. **Device:** 해당 기기로 푸시 알림 전달.

---

## 5. 실무 팁

### ✅ 에러 핸들링과 토큰 관리

* **Invalid Registration Token:** 사용자가 앱을 삭제하거나 토큰이 만료된 경우 `UNREGISTERED` 에러가 발생.
* **대처:** 이 에러가 발생하면 서버 DB에서 해당 토큰을 **즉시 삭제하거나 비활성화**하여 다음 발송 시 제외해야 성능 저하 방어 가능

### ✅ 비동기 발송

* 알림 발송은 외부 API 호출이므로 시간이 걸릴 수 있습니다.
* **해결:** `@Async` 등을 사용하여 별도 스레드에서 비동기로 처리해 사용자 응답 속도를 높여야 함.

### ✅ 환경별 분기 (Profile)

* 로컬 개발 환경에서 실제 푸시가 나가지 않도록 `application.yml` 설정에 따라 발송 로직을 활성화/비활성화 처리.
