# Terraform 기초 이론

## 1. Terraform이란?

HashiCorp이 개발한 **오픈소스 IaC(Infrastructure as Code) 도구**. 클라우드 인프라를 코드로 정의하고 자동으로 생성/수정/삭제하는 도구.

```
IaC (Infrastructure as Code)
= 인프라를 코드로 관리하는 방법론

콘솔 클릭 방식 (Before)
└── AWS 콘솔 접속
    → EC2 메뉴 클릭
    → 설정 하나하나 입력
    → 생성 버튼 클릭
    → 재현 불가능, 실수 가능성 높음

Terraform 방식 (After)
└── .tf 파일 작성
    → terraform apply 명령어 한 줄
    → 자동 생성, 재현 가능, 버전 관리 가능
```

> 📝 *Terraform은 AWS 전용이 아님. AWS, GCP, Azure, NCP 등 대부분의 클라우드 프로바이더를 동일한 문법으로 관리 가능.*

## 2. Terraform 핵심 개념

### Provider
Terraform이 **어떤 클라우드와 통신할지** 정의하는 플러그인.

```hcl
# AWS Provider 설정
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = "ap-northeast-2"    # 서울 리전
}
```

### Resource
실제로 **생성할 인프라 리소스**를 정의하는 블록.

```hcl
# EC2 인스턴스 생성
resource "aws_instance" "my_server" {
  ami           = "ami-0c9c942bd7bf113a2"  # Ubuntu 22.04
  instance_type = "t3.micro"

  tags = {
    Name = "my-server"
  }
}

# S3 버킷 생성
resource "aws_s3_bucket" "my_bucket" {
  bucket = "my-project-bucket-2024"

  tags = {
    Name = "my-bucket"
  }
}
```

### Variable
반복 사용하는 값을 **변수로 분리**해서 관리.

```hcl
# variables.tf
variable "instance_type" {
  description = "EC2 인스턴스 타입"
  type        = string
  default     = "t3.micro"
}

variable "region" {
  description = "AWS 리전"
  type        = string
  default     = "ap-northeast-2"
}

# main.tf에서 사용
resource "aws_instance" "my_server" {
  instance_type = var.instance_type    # var.변수명으로 참조
}
```

### Output이란?
Terraform 실행 후 **결과값을 출력**하는 블록.

```hcl
# EC2 생성 후 IP 주소 출력
output "ec2_public_ip" {
  description = "EC2 퍼블릭 IP"
  value       = aws_instance.my_server.public_ip
}
```

### State란?
Terraform이 **현재 인프라 상태를 추적**하는 파일 (`terraform.tfstate`).

```
terraform.tfstate
└── 현재 실제 인프라 상태가 JSON으로 저장됨
    └── Terraform은 이 파일 기준으로
        현재 상태 vs 코드 상태를 비교해서
        변경사항만 적용
```

> 📝 *tfstate 파일을 절대 Github/Gitlab에 올리면 안 됨. AWS 키, IP 등 민감 정보가 포함되어 있음. 반드시 .gitignore에 추가.*

## 3. Terraform 파일 구조

```
my-project/
├── main.tf          ← 핵심 리소스 정의
├── variables.tf     ← 변수 정의
├── outputs.tf       ← 출력값 정의
├── providers.tf     ← Provider 설정
├── terraform.tfvars ← 변수 실제값 입력 (gitignore 권장)
└── .gitignore
    └── *.tfstate
        *.tfvars      ← 민감 정보 포함 가능
```

> 📝 *파일을 무조건 이렇게 분리할 필요는 없음. 소규모 프로젝트는 main.tf 하나에 전부 작성해도 동작함. 규모가 커질수록 분리하는 것을 권장.*

## 4. Terraform 명령어 흐름이란?

```
.tf 파일 작성
      │
      ▼
terraform init
└── Provider 플러그인 다운로드
    .terraform 디렉토리 생성

      │
      ▼
terraform plan
└── 현재 상태 vs 코드 비교
    무엇이 생성/수정/삭제될지 미리 보여줌
    실제 인프라에는 변경 없음

      │
      ▼
terraform apply
└── plan 결과를 실제 인프라에 적용
    "yes" 입력 후 실행

      │
      ▼
terraform destroy
└── 모든 리소스 삭제
    "yes" 입력 후 실행
```

```bash
terraform init       # 초기화
terraform plan       # 변경사항 미리보기
terraform apply      # 실제 적용
terraform destroy    # 전체 삭제
terraform fmt        # 코드 자동 포맷팅
terraform validate   # 문법 검증
```

> 📝 *`terraform apply` 전에 반드시 `terraform plan` 결과를 꼼꼼히 읽는 습관 필수. `-/+` 표시는 리소스 삭제 후 재생성을 의미하므로 데이터 손실 가능성 있음.*

## 5. 실제 프로젝트 예시

EC2 + Security Group + Elastic IP를 Terraform으로 한 번에 생성하는 예시.

```hcl
# main.tf

# Security Group 생성
resource "aws_security_group" "web_sg" {
  name        = "web-security-group"
  description = "Web server security group"

  # SSH 허용
  ingress {
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = ["내_IP/32"]      # 내 IP만 허용
  }

  # HTTP 허용
  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  # HTTPS 허용
  ingress {
    from_port   = 443
    to_port     = 443
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  # 아웃바운드 전체 허용
  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

# EC2 생성
resource "aws_instance" "web_server" {
  ami                    = "ami-0c9c942bd7bf113a2"
  instance_type          = var.instance_type
  key_name               = "my-key-pair"
  vpc_security_group_ids = [aws_security_group.web_sg.id]

  user_data = <<-EOF
    #!/bin/bash
    apt update
    apt install -y docker.io
    systemctl enable docker
  EOF

  tags = {
    Name = "web-server"
  }
}

# Elastic IP 생성 및 연결
resource "aws_eip" "web_eip" {
  instance = aws_instance.web_server.id
  domain   = "vpc"
}
```

```hcl
# outputs.tf
output "web_server_ip" {
  value = aws_eip.web_eip.public_ip
}
```

## 6. Remote State란?

팀 프로젝트에서 tfstate 파일을 **팀원 모두가 공유**해야 할 때 사용. S3에 저장하는 방식이 표준.

```hcl
# backend.tf
terraform {
  backend "s3" {
    bucket = "my-terraform-state"    # S3 버킷
    key    = "project/terraform.tfstate"
    region = "ap-northeast-2"
  }
}
```

```
로컬 State (비권장)
└── 팀원 각자 tfstate 파일이 달라짐
    → 인프라 충돌 발생

Remote State (권장)
└── S3에 tfstate 중앙 관리
    → 팀원 모두 동일한 상태 공유
    → 동시 수정 방지 (DynamoDB로 Lock 설정 가능)
```

> 📝 *6주 프로젝트에서 Terraform을 도입한다면 Remote State 설정을 처음부터 잡아두는 것을 권장. 나중에 바꾸려면 번거로움.*

## 7. Gitlab CI/CD와 Terraform 연동

```yaml
# .gitlab-ci.yml
stages:
  - validate
  - plan
  - apply

terraform-validate:
  stage: validate
  image: hashicorp/terraform:latest
  script:
    - terraform init
    - terraform validate

terraform-plan:
  stage: plan
  image: hashicorp/terraform:latest
  script:
    - terraform init
    - terraform plan
  only:
    - merge_requests          # MR 생성 시 자동으로 plan 실행

terraform-apply:
  stage: apply
  image: hashicorp/terraform:latest
  script:
    - terraform init
    - terraform apply -auto-approve
  only:
    - main                    # main 브랜치 머지 시만
  when: manual                # 수동 실행
```

> 📝 *Terraform apply는 반드시 `when: manual` 로 설정. 자동으로 인프라가 변경되면 예기치 않은 리소스 삭제/변경이 발생할 수 있음.*

## Terraform 이론 정리

```
Terraform 핵심
├── 정의          ← 인프라를 코드로 관리하는 IaC 도구
├── 핵심 개념
│   ├── Provider  ← 어떤 클라우드와 통신할지
│   ├── Resource  ← 생성할 인프라 리소스
│   ├── Variable  ← 재사용 변수
│   ├── Output    ← 결과값 출력
│   └── State     ← 현재 인프라 상태 추적 (gitignore 필수)
├── 명령어 흐름   ← init → plan → apply → destroy
├── Remote State  ← S3에 tfstate 중앙 관리 (팀 프로젝트 필수)
└── CI/CD 연동    ← plan은 자동, apply는 수동(when: manual)
```
