# Linux 기초 이론

## 1. Linux란?

Linux는 **오픈소스 운영체제**.
Windows, macOS처럼 컴퓨터를 동작시키는 OS인데 서버 환경에서는 Linux가 표준.
AWS EC2도 기본적으로 Linux 위에서 돌아감.

```
전 세계 서버의 약 96%가 Linux 기반
```

## 2. 파일 시스템 구조

Windows는 `C:\Users\...` 형태지만, Linux는 `/` (루트)에서 시작하는 트리 구조야.

```
/ (루트)
├── /home       # 사용자 개인 디렉토리 (Windows의 C:\Users)
├── /etc        # 설정 파일 모음 (nginx, docker 설정 등)
├── /var        # 로그, 데이터 등 자주 변하는 파일
│   └── /var/log  # 시스템/앱 로그 파일
├── /usr        # 설치된 프로그램들
├── /tmp        # 임시 파일 (재부팅하면 삭제)
├── /bin        # 기본 명령어 실행 파일 (ls, cp 등)
└── /root       # root 계정의 홈 디렉토리
```

> Infra 작업할 때 가장 자주 가는 곳은 `/etc` (설정), `/var/log` (로그), `/home` (내 작업공간) 이 세 곳. 이것만 기억해도 됨

## 3. 권한 시스템

Linux는 **모든 파일에 권한**이 있음. 
`ls -l` 명령어를 치면 나옴

```bash
-rwxr-xr-- 1 ubuntu ubuntu 1234 Mar 1 12:00 app.sh
```

```
- rwx r-x r--
│  │   │   └── Others(다른 사용자): 읽기만 가능
│  │   └────── Group(그룹): 읽기 + 실행 가능
│  └────────── Owner(소유자): 읽기 + 쓰기 + 실행 가능
└───────────── 파일 타입 (- 파일 / d 디렉토리)
```

권한은 숫자로도 표현 가능

| 숫자 | 의미 |
|------|------|
| 7 | rwx (읽기+쓰기+실행) |
| 6 | rw- (읽기+쓰기) |
| 5 | r-x (읽기+실행) |
| 4 | r-- (읽기만) |

```bash
chmod 755 app.sh   # 소유자는 모든 권한, 나머지는 읽기+실행
chmod 600 key.pem  # EC2 접속할 때 pem 파일에 이 권한 줘야 함
```

> EC2 SSH 접속할 때 `WARNING: UNPROTECTED PRIVATE KEY FILE!` 에러가 나면 `chmod 400 key.pem` 으로 해결 가능

## 4. 프로세스 관리

서버에서 앱이 실행 중인지, 얼마나 자원을 쓰는지 확인하는 개념

```
프로세스 = 실행 중인 프로그램
PID = 프로세스 고유 ID 번호
```

| 명령어 | 역할 |
|--------|------|
| `ps aux` | 현재 실행 중인 모든 프로세스 목록 |
| `top` | 실시간 CPU/메모리 사용 현황 (Windows 작업관리자랑 비슷) |
| `kill -9 PID` | 특정 프로세스 강제 종료 |
| `grep` | 원하는 내용 필터링 |

```bash
# 예시: nginx 프로세스가 실행 중인지 확인
ps aux | grep nginx
#     └── | (파이프) : 앞 명령어 결과를 뒤 명령어에 전달
```

> `|` (파이프) 개념이 Linux에서 엄청 중요함! 명령어를 조합해서 쓸 수 있게 해주는 핵심 문법

## 5. 패키지 관리자

Linux는 **패키지 관리자**로 프로그램 설치

```bash
# Ubuntu/Debian 계열 (EC2 Ubuntu 기준)
sudo apt update           # 설치 가능한 패키지 목록 최신화
sudo apt install nginx    # nginx 설치
sudo apt remove nginx     # nginx 삭제

# Amazon Linux 계열
sudo yum install nginx
# 또는
sudo dnf install nginx
```

> 뭔가 설치하기 전에 `apt update` 먼저 하는 습관을 들이자! (안 하면 오래된 버전이 설치되거나 에러가 나는 경우가 많음)

## 6. Shell Script 기초 개념

여러 명령어를 순서대로 자동 실행하는 **자동화 스크립트**. CI/CD 파이프라인에서도 결국 shell script를 쓰게 될 것임

```bash
#!/bin/bash              # 이 파일이 bash 스크립트임을 선언

# 변수
NAME="my-app"

# 조건문
if [ -f "docker-compose.yml" ]; then
  echo "파일 있음"
else
  echo "파일 없음"
fi

# 반복문
for i in 1 2 3; do
  echo "count: $i"
done
```

> 지금 당장 완벽하게 짤 필요 없음. `#!/bin/bash` 로 시작하고, 명령어를 순서대로 나열하는 것만 알아도 실무에서 충분히 써먹을 수 있음.

## 이론 정리

```
Linux 기초 이론
├── 파일 시스템 구조  ← /etc, /var/log, /home 기억
├── 권한 시스템       ← chmod, pem 파일은 chmod 400
├── 프로세스 관리     ← ps, top, kill, | 파이프
├── 패키지 관리자     ← apt update && apt install
└── Shell Script      ← #!/bin/bash 로 시작
```
