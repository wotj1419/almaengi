# Nginx + HTTPS 기초 이론

## 1. Nginx란?

**웹 서버 + 리버스 프록시** 역할을 하는 소프트웨어 (현재 전 세계 웹 서버 점유율 1위)

```
Nginx 주요 역할
├── 웹 서버        ← 정적 파일 (HTML, CSS, JS) 직접 서빙
├── 리버스 프록시  ← 외부 요청을 내부 서버로 전달
├── 로드 밸런서    ← 여러 서버에 트래픽 분산
└── SSL 종료       ← HTTPS 처리
```

## 2. 리버스 프록시란?

클라이언트와 서버 사이에서 **중간 다리 역할**을 해.

```
리버스 프록시 없을 때
클라이언트 → :8080 (Spring Boot 직접 접근)
클라이언트 → :3000 (React 직접 접근)
→ 포트번호 노출, HTTPS 적용 어려움

리버스 프록시 있을 때
클라이언트 → :80/:443 (Nginx)
                  │
                  ├── /api/*   → :8080 (Spring Boot)
                  └── /*       → :3000 (React)
→ 포트 통일, HTTPS 한 곳에서 처리
```

실제 프로젝트 구조

```
인터넷
    │
    ▼
Nginx (80/443)
    │
    ├── /api 요청 → Backend (8080)
    ├── /  요청   → Frontend (3000)
    └── /static  → S3 or 로컬 파일
```

## 3. Nginx 설정 파일 구조

```nginx
# /etc/nginx/nginx.conf 기본 구조

http {
    # 여러 서버 블록 포함
    include /etc/nginx/sites-enabled/*;
}
```

```nginx
# /etc/nginx/sites-available/my-app.conf

server {
    listen 80;                        # HTTP 포트
    server_name myapp.com;            # 도메인

    # /api 로 시작하는 요청 → 백엔드로
    location /api {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 나머지 요청 → 프론트엔드로
    location / {
        proxy_pass http://localhost:3000;
    }
}
```

> `sites-available`에 설정 파일 만들고, `sites-enabled`에 심볼릭 링크를 걸어야 활성화됨. `sudo ln -s /etc/nginx/sites-available/my-app.conf /etc/nginx/sites-enabled/` 이렇게 하면 됨.

## 4. HTTPS

HTTP에 **암호화(SSL/TLS)를 추가**한 보안 프로토콜

```
HTTP  = 데이터를 그냥 전송 (누군가 가로채면 내용 그대로 보임)
HTTPS = 데이터를 암호화해서 전송 (가로채도 해독 불가)
```

```
왜 HTTPS가 필수냐?
├── 로그인 정보, 개인정보 보호
├── 브라우저 주소창 🔒 자물쇠 표시
├── SEO 점수 향상
└── 크롬에서 HTTP 사이트 "안전하지 않음" 경고 표시
```

## 5. SSL 인증서 종류

| 종류 | 비용 | 용도 |
|------|------|------|
| Let's Encrypt | **무료** | 개인/프로젝트 ← 이걸 써 |
| 유료 인증서 | 수만~수백만원 | 기업 서비스 |
| 자체 서명 인증서 | 무료 | 내부 테스트용 |

> Let's Encrypt는 **90일마다 갱신**이 필요. 근데 Certbot이 자동 갱신까지 해줌. 설치하면 cron job이 자동으로 등록돼서 신경 안 써도 됨.

## 6. Certbot으로 HTTPS 적용하기

**Certbot**은 Let's Encrypt 인증서를 자동으로 발급/설치/갱신해주는 도구

```bash
# 1. Certbot 설치 (Ubuntu 기준)
sudo apt install certbot python3-certbot-nginx

# 2. 인증서 발급 + Nginx 자동 설정
sudo certbot --nginx -d myapp.com -d www.myapp.com

# 3. 자동 갱신 테스트
sudo certbot renew --dry-run
```

Certbot 실행 후 Nginx 설정이 자동으로 이렇게 바뀜.

```nginx
server {
    listen 80;
    server_name myapp.com;
    # HTTP → HTTPS 자동 리다이렉트 추가됨
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;               # HTTPS 포트
    server_name myapp.com;

    # 인증서 경로 자동 추가
    ssl_certificate /etc/letsencrypt/live/myapp.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/myapp.com/privkey.pem;

    location /api {
        proxy_pass http://localhost:8080;
    }

    location / {
        proxy_pass http://localhost:3000;
    }
}
```

> Certbot이 도메인 소유 확인을 위해 **80포트가 열려있어야** 함. Security Group에서 80포트 인바운드 허용 확인 먼저 함.

## 7. 도메인 연결 흐름

HTTPS를 적용하려면 도메인이 있어야 함.

```
도메인 구매 (가비아, Route 53 등)
    │
    ▼
DNS A 레코드 설정
myapp.com → EC2 Elastic IP 연결
    │
    ▼
EC2 Security Group
80, 443 포트 인바운드 허용
    │
    ▼
Nginx 설치 및 설정
    │
    ▼
Certbot으로 SSL 인증서 발급
    │
    ▼
🔒 https://myapp.com 접속 가능!
```

## 8. Docker 환경에서 Nginx 사용하기

EC2에 Nginx를 직접 설치할 수도 있고, **Docker 컨테이너로 띄울 수도** 있음

```yaml
# docker-compose.yml에 Nginx 추가
services:
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf  # 설정 파일 마운트
      - /etc/letsencrypt:/etc/letsencrypt          # 인증서 마운트
    depends_on:
      - backend
      - frontend

  backend:
    build: ./backend
    expose:
      - "8080"          # 외부 노출 안하고 내부 통신만

  frontend:
    build: ./frontend
    expose:
      - "3000"
```

> `ports`는 외부에 포트를 노출하고, `expose`는 컨테이너끼리만 통신할 때 씀. Backend, Frontend는 Nginx를 통해서만 접근하도록 `expose`만 쓰는 게 보안상 올바른 방식.

## Nginx + HTTPS 이론 정리

```
Nginx + HTTPS 핵심
├── Nginx
│   ├── 웹 서버        ← 정적 파일 서빙
│   ├── 리버스 프록시  ← 요청을 내부 서버로 전달
│   └── 설정 파일      ← /etc/nginx/sites-available/
├── HTTPS
│   ├── SSL/TLS 암호화 ← 데이터 보호
│   └── Let's Encrypt  ← 무료 인증서
├── Certbot
│   ├── 인증서 자동 발급
│   └── 자동 갱신
└── Docker 연동
    ├── ports  ← 외부 노출
    └── expose ← 내부 통신만
```
