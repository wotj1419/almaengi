# Monitoring 기초 이론

## 1. Monitoring이란?

서비스가 **정상적으로 동작하는지 지속적으로 관찰**하고, 문제 발생 시 즉시 감지하는 행위.

```
Monitoring이 없을 때
└── 서버 다운 → 사용자 신고 → 개발자 확인 → 조치
    (사용자가 먼저 장애를 발견)

Monitoring이 있을 때
└── 서버 다운 → 즉시 알람 → 개발자 확인 → 조치
    (개발자가 먼저 장애를 발견)
```

```
Monitoring 3대 요소
├── Metrics  ← 숫자로 표현되는 시스템 상태 (CPU, 메모리 등)
├── Logs     ← 시스템/앱에서 발생하는 텍스트 기록
└── Traces   ← 요청이 시스템을 통과하는 전체 경로 추적
```

> 📝 *세 가지를 모두 갖추는 것이 이상적이나, 입문 단계에서는 Metrics + Logs 두 가지만 구축해도 충분.*

## 2. Prometheus

### Prometheus 개요

오픈소스 **메트릭 수집 및 저장 도구**. 시스템의 CPU, 메모리, 네트워크 등 숫자 데이터를 주기적으로 수집해서 시계열 DB에 저장.

```
Prometheus 특징
├── Pull 방식  ← Prometheus가 직접 대상 서버에서 메트릭을 가져옴
├── 시계열 DB  ← 시간 흐름에 따른 데이터 저장에 최적화
├── PromQL     ← 메트릭 조회 전용 쿼리 언어
└── Alertmanager ← 조건 충족 시 알람 발송
```

```
Pull 방식 동작 흐름
Prometheus → (15초마다) → /metrics 엔드포인트 요청
                              │
              ← 메트릭 데이터 반환 ←
```

> 📝 *Push 방식(앱이 데이터를 보냄)과 Pull 방식(Prometheus가 데이터를 가져옴)의 차이를 이해하는 것이 중요. Prometheus는 Pull 방식이라 모니터링 대상 서버에 Exporter 설치가 필요.*

### Exporter

Prometheus가 메트릭을 수집할 수 있도록 **대상 서버에 설치하는 에이전트**.

```
Exporter 종류
├── Node Exporter      ← 서버 자체 메트릭 (CPU, 메모리, 디스크)
├── cAdvisor           ← Docker 컨테이너 메트릭
├── MySQL Exporter     ← MySQL DB 메트릭
└── Nginx Exporter     ← Nginx 메트릭
```

```
EC2 서버
└── Node Exporter 실행 중
    └── :9100/metrics 엔드포인트 노출
              ↑
        Prometheus가 주기적으로 수집
```

### PromQL

Prometheus에서 메트릭을 **조회하는 쿼리 언어**.

```promql
# CPU 사용률 조회
100 - (avg by(instance)(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)

# 메모리 사용률 조회
(1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes) * 100

# 특정 컨테이너 CPU 사용량
rate(container_cpu_usage_seconds_total{name="backend"}[5m])
```

> 📝 *PromQL을 처음부터 외울 필요 없음. Grafana 대시보드에서 자주 쓰는 쿼리는 커뮤니티에서 공유된 템플릿을 가져다 쓰면 됨.*

## 3. Grafana

### Grafana 개요

Prometheus 등 다양한 데이터 소스를 연결해서 **시각화 대시보드를 만드는 도구**.

```
Prometheus  →  데이터 수집/저장
Grafana     →  데이터 시각화
```

```
Grafana 주요 기능
├── 대시보드   ← 메트릭을 그래프/차트로 시각화
├── 알람       ← 조건 충족 시 Slack, 이메일 알림
├── 데이터소스 ← Prometheus, MySQL, CloudWatch 등 연결
└── 템플릿     ← 커뮤니티 공유 대시보드 import 가능
```

> 📝 *Grafana 대시보드는 처음부터 만들 필요 없음. grafana.com/grafana/dashboards 에서 Node Exporter, Docker 등 검색하면 완성된 템플릿을 숫자 하나로 import 가능.*

### Grafana 대시보드 구성

```
Dashboard
└── Panel (여러 개)
    ├── Graph Panel   ← 시계열 그래프
    ├── Stat Panel    ← 현재 값 하나 표시
    ├── Gauge Panel   ← 게이지 형태
    └── Table Panel   ← 테이블 형태
```

## 4. Prometheus + Grafana 아키텍처

```
EC2 서버들
├── Node Exporter (:9100)   ← 서버 메트릭 노출
├── cAdvisor (:8080)        ← 컨테이너 메트릭 노출
└── App Metrics (:8080/metrics)

          ↑ Pull (15초마다)

Prometheus (:9090)
└── 메트릭 수집 및 저장
    └── Alertmanager
        └── 조건 충족 시 알람 발송

          ↓ 쿼리

Grafana (:3000)
└── 대시보드 시각화
    └── 알람 설정 (Slack, 이메일)
```

## 5. docker-compose로 구축하기

```yaml
# docker-compose.yml
version: '3.8'

services:
  prometheus:
    image: prom/prometheus:latest
    ports:
      - "9090:9090"
    volumes:
      - ./prometheus/prometheus.yml:/etc/prometheus/prometheus.yml
      - prometheus-data:/prometheus
    command:
      - '--config.file=/etc/prometheus/prometheus.yml'

  grafana:
    image: grafana/grafana:latest
    ports:
      - "3000:3000"
    volumes:
      - grafana-data:/var/lib/grafana
    environment:
      - GF_SECURITY_ADMIN_PASSWORD=admin123
    depends_on:
      - prometheus

  node-exporter:
    image: prom/node-exporter:latest
    ports:
      - "9100:9100"
    volumes:
      - /proc:/host/proc:ro
      - /sys:/host/sys:ro
    command:
      - '--path.procfs=/host/proc'
      - '--path.sysfs=/host/sys'

volumes:
  prometheus-data:
  grafana-data:
```

```yaml
# prometheus/prometheus.yml
global:
  scrape_interval: 15s        # 15초마다 메트릭 수집

scrape_configs:
  - job_name: 'node-exporter'
    static_configs:
      - targets: ['node-exporter:9100']

  - job_name: 'cadvisor'
    static_configs:
      - targets: ['cadvisor:8080']
```

> 📝 *Grafana 초기 접속 후 Data Source에서 Prometheus URL을 `http://prometheus:9090` 으로 설정. 같은 docker-compose 네트워크 안이라 컨테이너명으로 통신 가능.*

## 6. Alertmanager

Prometheus에서 **알람 조건을 정의**하고, 조건 충족 시 Slack/이메일로 알림을 발송하는 도구.

```yaml
# prometheus/alert.rules.yml
groups:
  - name: server_alerts
    rules:
      # CPU 80% 초과 시 알람
      - alert: HighCPUUsage
        expr: 100 - (avg(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 80
        for: 2m                     # 2분 이상 지속될 때만 알람
        labels:
          severity: warning
        annotations:
          summary: "CPU 사용률 높음"
          description: "CPU 사용률이 80%를 초과했습니다."

      # 디스크 90% 초과 시 알람
      - alert: DiskSpaceLow
        expr: (node_filesystem_avail_bytes / node_filesystem_size_bytes) * 100 < 10
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "디스크 여유 공간 부족"
```

```yaml
# alertmanager/config.yml
route:
  receiver: 'slack-notifications'

receivers:
  - name: 'slack-notifications'
    slack_configs:
      - api_url: 'https://hooks.slack.com/services/xxx'
        channel: '#alerts'
        title: '{{ .CommonAnnotations.summary }}'
        text: '{{ .CommonAnnotations.description }}'
```

> 📝 *알람은 너무 민감하게 설정하면 알람 피로(Alert Fatigue)가 생김. `for` 옵션으로 일정 시간 이상 지속될 때만 알람이 오도록 설정하는 것을 권장.*

## 7. Loki (로그 수집)

Grafana에서 만든 **로그 수집 및 조회 도구**. ELK Stack보다 가볍고 Grafana와 연동이 쉬움.

```
ELK Stack (Elasticsearch + Logstash + Kibana)
└── 기능 풍부하지만 무거움, 메모리 많이 사용

Grafana Loki
└── 가볍고 빠름, Grafana와 네이티브 연동
    → 입문자에게 권장
```

```
Loki 구성요소
├── Loki       ← 로그 저장 및 인덱싱
├── Promtail   ← 각 서버에서 로그를 수집해서 Loki로 전송
└── Grafana    ← 로그 시각화 및 검색
```

```yaml
# docker-compose.yml에 Loki + Promtail 추가
  loki:
    image: grafana/loki:latest
    ports:
      - "3100:3100"

  promtail:
    image: grafana/promtail:latest
    volumes:
      - /var/log:/var/log:ro              # 시스템 로그
      - /var/lib/docker/containers:/var/lib/docker/containers:ro  # 컨테이너 로그
      - ./promtail/config.yml:/etc/promtail/config.yml
```

> 📝 *Grafana에 Loki를 Data Source로 추가하면 메트릭(Prometheus)과 로그(Loki)를 하나의 대시보드에서 함께 볼 수 있음. 장애 발생 시 메트릭 이상 감지 → 해당 시점 로그 바로 확인 가능.*

## 8. CloudWatch와 비교

| 항목 | Prometheus + Grafana | CloudWatch |
|------|----------------------|------------|
| 비용 | 무료 (서버 비용만) | 사용량 기반 과금 |
| 설치 | 직접 구축 필요 | AWS 기본 제공 |
| 커스터마이징 | 자유도 높음 | 제한적 |
| AWS 연동 | 별도 설정 필요 | 네이티브 연동 |
| 메모리 메트릭 | Node Exporter로 수집 | Agent 설치 필요 |

```
6주 프로젝트 권장 구성
├── CloudWatch  ← EC2 기본 메트릭 + 알람 (빠른 설정)
└── Grafana + Prometheus ← 커스텀 대시보드 (여유 있을 때)
```

> 📝 *시간이 부족하다면 CloudWatch 알람만 설정해도 충분. CPU/디스크 알람 + 이메일 연동은 5분이면 설정 가능.*

## Monitoring 이론 정리

```
Monitoring 핵심
├── 3대 요소      ← Metrics, Logs, Traces
├── Prometheus
│   ├── 메트릭 수집/저장  ← Pull 방식
│   ├── Exporter          ← 대상 서버에 설치하는 에이전트
│   ├── PromQL            ← 메트릭 조회 쿼리 언어
│   └── Alertmanager      ← 알람 발송
├── Grafana
│   ├── 시각화 대시보드   ← 템플릿 import 활용
│   └── 알람              ← Slack, 이메일 연동
├── Loki          ← 가벼운 로그 수집 (ELK 대안)
└── CloudWatch    ← AWS 기본 모니터링 (빠른 설정)
```
