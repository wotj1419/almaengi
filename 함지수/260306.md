# 네트워크 기초 / VPC 심화

## 1. 네트워크 기초 개념

VPC를 이해하려면 네트워크 기초 개념을 먼저 잡아야 함.

### IP 주소

네트워크에서 **각 장치를 구별하는 고유 주소**.

```
IPv4 주소 구조
192  .  168  .   1  .   1
 │        │       │      │
 └────────┴───────┴──────┘
      32비트 (4개 옥텟)
```

```
IP 주소 종류
├── 공인 IP (Public IP)
│   └── 인터넷에서 직접 접근 가능한 주소
│       예) EC2 퍼블릭 IP, 집 공유기 외부 IP
│
└── 사설 IP (Private IP)
    └── 내부 네트워크에서만 사용하는 주소
        예) 192.168.x.x / 10.x.x.x / 172.16.x.x
```

### CIDR 표기법

IP 주소 범위를 표현하는 방식.

```
10.0.0.0/16
        │
        └── 앞에서 16비트를 네트워크 주소로 고정
            나머지 16비트가 호스트 주소
            → 사용 가능한 IP 수 : 2^16 = 65,536개

10.0.1.0/24
        │
        └── 앞에서 24비트 고정
            나머지 8비트가 호스트 주소
            → 사용 가능한 IP 수 : 2^8 = 256개
```

```
숫자가 클수록 범위가 좁아짐
/16  →  65,536개  (VPC 전체 범위로 주로 사용)
/24  →     256개  (Subnet 범위로 주로 사용)
/32  →       1개  (특정 IP 하나 지정할 때)
```

> 📝 *Security Group에서 `내_IP/32` 로 설정하면 딱 내 IP 하나만 허용하는 것. CIDR 표기법을 이해하면 Security Group 설정이 훨씬 직관적으로 이해됨.*

### 포트

같은 IP에서 **여러 서비스를 구분**하는 번호.

```
IP 주소 = 건물 주소
포트    = 건물 내 호수

10.0.0.1:80   → 80호  (HTTP)
10.0.0.1:443  → 443호 (HTTPS)
10.0.0.1:22   → 22호  (SSH)
10.0.0.1:3306 → 3306호 (MySQL)
```

```
자주 쓰는 포트 번호
├── 22    ← SSH
├── 80    ← HTTP
├── 443   ← HTTPS
├── 3306  ← MySQL
├── 5432  ← PostgreSQL
├── 6379  ← Redis
├── 8080  ← 앱 서버 (Spring Boot 기본값)
└── 9090  ← Prometheus
```

## 2. VPC 핵심 구성요소

### VPC (Virtual Private Cloud)

AWS 안에 만드는 **논리적으로 격리된 가상 네트워크**.

```
AWS 전체
└── 내 계정
    └── VPC (10.0.0.0/16)   ← 내 전용 네트워크 공간
        ├── Subnet A
        ├── Subnet B
        └── Subnet C
```

```
VPC 기본 설정
├── CIDR 블록 지정  ← 전체 IP 범위 설정 (예: 10.0.0.0/16)
├── 리전 단위       ← VPC는 하나의 리전에 속함
└── 계정당 기본 VPC ← AWS가 자동 생성해주는 Default VPC 존재
```

> 📝 *Default VPC는 편하지만 보안 설정이 느슨함. 실제 프로젝트에서는 VPC를 직접 생성해서 사용하는 것을 권장.*

### Subnet

VPC를 **더 작은 네트워크로 분할**한 단위. AZ(가용영역) 단위로 생성.

```
VPC (10.0.0.0/16)
├── Public Subnet  (10.0.1.0/24)  - AZ-a
│   └── 인터넷에서 직접 접근 가능
│       EC2 (웹 서버), NAT Gateway, Load Balancer
│
├── Public Subnet  (10.0.2.0/24)  - AZ-b  ← 이중화
│
├── Private Subnet (10.0.3.0/24)  - AZ-a
│   └── 인터넷에서 직접 접근 불가
│       EC2 (앱 서버), RDS (DB)
│
└── Private Subnet (10.0.4.0/24)  - AZ-b  ← 이중화
```

```
Public Subnet  = 인터넷 게이트웨이 경로 있음
Private Subnet = 인터넷 게이트웨이 경로 없음
```

### Internet Gateway (IGW)

VPC와 **인터넷을 연결**하는 관문.

```
인터넷
  │
  ▼
Internet Gateway
  │
  ▼
Public Subnet의 EC2   ← 인터넷 통신 가능
```

> 📝 *IGW는 VPC당 하나만 연결 가능. Public Subnet의 Route Table에 IGW로 향하는 경로(0.0.0.0/0)가 있어야 인터넷 통신이 됨.*

### NAT Gateway

**Private Subnet의 EC2가 인터넷에 접근**할 때 사용. 반대로 인터넷에서 Private Subnet으로 직접 접근은 불가.

```
Private Subnet EC2
  │  (패키지 설치, 외부 API 호출 등)
  ▼
NAT Gateway (Public Subnet에 위치)
  │
  ▼
Internet Gateway
  │
  ▼
인터넷
```

```
NAT Gateway 특징
├── Public Subnet에 위치
├── 아웃바운드(나가는) 트래픽만 허용
├── 인바운드(들어오는) 직접 접근 차단
└── 비용 발생 (시간당 약 $0.045 + 데이터 전송 비용)
```

> 📝 *NAT Gateway는 비용이 꽤 나옴. 6주 프로젝트에서 비용이 부담되면 Private Subnet 대신 Public Subnet에 EC2를 올리고 Security Group으로 접근을 제한하는 방식도 현실적인 대안.*

### Route Table

**트래픽이 어디로 이동할지 경로를 정의**하는 규칙 테이블.

```
Public Subnet Route Table
├── 10.0.0.0/16  →  local        (VPC 내부 통신)
└── 0.0.0.0/0    →  IGW          (나머지는 인터넷으로)

Private Subnet Route Table
├── 10.0.0.0/16  →  local        (VPC 내부 통신)
└── 0.0.0.0/0    →  NAT Gateway  (나머지는 NAT 통해서)
```

### Security Group

EC2 인스턴스 단위의 **가상 방화벽**.

```
Security Group 특징
├── 인스턴스 단위 적용
├── Stateful  ← 인바운드 허용하면 아웃바운드 자동 허용
├── 허용 규칙만 설정 (거부 규칙 없음)
└── 여러 인스턴스에 동일한 SG 적용 가능
```

```
Security Group 체이닝 (실무 패턴)
├── Web SG     ← 80, 443 전체 허용 (0.0.0.0/0)
├── App SG     ← 8080 허용, 단 Web SG에서 오는 트래픽만
└── DB SG      ← 3306 허용, 단 App SG에서 오는 트래픽만
```

> 📝 *IP 주소 대신 Security Group ID를 소스로 지정 가능. 예를 들어 DB SG의 인바운드에 App SG ID를 소스로 설정하면, App SG가 붙은 EC2에서만 DB에 접근 가능. IP가 바뀌어도 자동 반영.*

### NACL (Network ACL)

**Subnet 단위의 방화벽**. Security Group과 함께 이중 방어선 역할.

```
Security Group vs NACL
┌─────────────────┬──────────────┬──────────────┐
│ 항목            │ Security Group│    NACL      │
├─────────────────┼──────────────┼──────────────┤
│ 적용 단위       │ 인스턴스     │  Subnet      │
│ 상태            │ Stateful     │  Stateless   │
│ 규칙 종류       │ 허용만       │  허용 + 거부 │
│ 규칙 적용 순서  │ 전체 평가    │  번호 순서대로│
└─────────────────┴──────────────┴──────────────┘
```

> 📝 *NACL은 Stateless라서 인바운드 허용해도 아웃바운드를 별도로 허용해야 함. 초급 단계에서는 Security Group만 잘 설정해도 충분. NACL은 추가 보안이 필요할 때 적용.*

## 3. VPC 전체 아키텍처

실제 프로젝트에서 권장하는 구조.

```
인터넷
    │
    ▼
Internet Gateway
    │
    ▼
┌─────────────────────────────────────┐
│  VPC (10.0.0.0/16)                  │
│                                     │
│  ┌──────────────────────────────┐   │
│  │  Public Subnet (10.0.1.0/24) │   │
│  │  ├── Nginx EC2 (80/443)      │   │
│  │  └── NAT Gateway             │   │
│  └──────────────────────────────┘   │
│              │                      │
│              │ 내부 통신             │
│              ▼                      │
│  ┌──────────────────────────────┐   │
│  │ Private Subnet (10.0.2.0/24) │   │
│  │  ├── Backend EC2 (8080)      │   │
│  │  └── DB EC2 (3306)           │   │
│  └──────────────────────────────┘   │
└─────────────────────────────────────┘
```

## 4. VPC 구성 흐름

Terraform 또는 AWS 콘솔에서 VPC를 구성하는 순서.

```
1. VPC 생성
   └── CIDR: 10.0.0.0/16

2. Subnet 생성
   ├── Public Subnet  : 10.0.1.0/24
   └── Private Subnet : 10.0.2.0/24

3. Internet Gateway 생성 및 VPC에 연결

4. Route Table 설정
   ├── Public RT  : 0.0.0.0/0 → IGW 연결
   └── Private RT : 0.0.0.0/0 → NAT Gateway 연결

5. NAT Gateway 생성
   └── Public Subnet에 위치, Elastic IP 연결

6. Security Group 설정
   ├── Web SG  : 80, 443 허용
   ├── App SG  : 8080 허용 (Web SG에서만)
   └── DB SG   : 3306 허용 (App SG에서만)

7. EC2 생성 및 Subnet/SG 연결
```

> 📝 *순서가 중요함. IGW → Route Table → NAT Gateway 순으로 잡아야 의존성 오류가 안 남. Terraform으로 구성하면 의존성을 자동으로 처리해줌.*

## 5. Bastion Host

**Private Subnet의 EC2에 SSH 접속하기 위한 중간 서버**.

```
외부에서 Private EC2에 직접 SSH 접속 불가
    ↓
해결책 : Bastion Host (점프 서버)

외부
  │  SSH
  ▼
Bastion Host (Public Subnet)
  │  SSH
  ▼
Private EC2 (Private Subnet)
```

```bash
# Bastion Host를 통한 SSH 접속 (로컬에서)
ssh -i key.pem -J ubuntu@bastion_ip ubuntu@private_ec2_ip
#              └── -J : 점프 호스트 지정 옵션
```

> 📝 *Bastion Host는 SSH(22번 포트)만 열어두고, 내 IP만 허용하는 것이 원칙. 6주 프로젝트에서는 비용/복잡도 때문에 생략하는 경우도 많지만, 개념은 알아둬야 함.*

## 네트워크 기초 / VPC 심화 이론 정리

```
네트워크 / VPC 핵심
├── 기초 개념
│   ├── IP 주소   ← 공인 IP / 사설 IP
│   ├── CIDR      ← IP 범위 표기법 (/16, /24, /32)
│   └── 포트      ← 같은 IP에서 서비스 구분
│
├── VPC 구성요소
│   ├── VPC             ← 격리된 가상 네트워크
│   ├── Subnet          ← Public / Private 분리
│   ├── Internet Gateway← VPC ↔ 인터넷 연결
│   ├── NAT Gateway     ← Private → 인터넷 (단방향)
│   ├── Route Table     ← 트래픽 경로 정의
│   ├── Security Group  ← 인스턴스 단위 방화벽 (Stateful)
│   └── NACL            ← Subnet 단위 방화벽 (Stateless)
│
└── Bastion Host  ← Private EC2 SSH 접속용 중간 서버
```
