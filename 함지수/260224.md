# Docker 기초 이론

## 1. Docker란?

한 줄로 표현하면 **"내 컴퓨터에서 되는데 서버에서 안 돼요"를 해결하는 기술**

Docker는 **앱 실행에 필요한 모든 환경을 컨테이너라는 박스에 담아서** 어디서든 동일하게 실행할 수 있게 해줌

## 2. 핵심 개념 3가지

### Image
컨테이너를 만들기 위한 **설계도 / 틀**
읽기 전용이고 변경이 안 됨

> Image = 붕어빵 틀

### Container
이미지를 실행한 **실제 인스턴스**
이미지 하나로 컨테이너를 여러 개 만들 수 있음

> Container = 붕어빵 틀로 찍어낸 붕어빵

### Dockerfile
이미지를 만들기 위한 **레시피 파일**
어떤 OS, 어떤 패키지, 어떤 명령어로 이미지를 만들지 정의

> Dockerfile → (build) → Image → (run) → Container

## 3. VM vs Container

Docker 이전엔 **VM**을 썼음

```
VM
┌──────────────────────────┐
│  App A  │  App B  │ App C│
│  OS     │  OS     │  OS  │  ← OS를 각각 설치
│  (2GB)  │  (2GB)  │(2GB) │  ← 무거움
├──────────────────────────┤
│       Hypervisor         │
│       Host OS            │
└──────────────────────────┘

Container
┌──────────────────────────┐
│  App A  │  App B  │ App C│
│  Deps   │  Deps   │ Deps │  ← 앱과 의존성만 포함
├──────────────────────────┤
│       Docker Engine      │  ← OS는 Host것을 공유
│       Host OS            │
└──────────────────────────┘
```

| | VM | Container |
|---|---|---|
| 시작 시간 | 수 분 | 수 초 |
| 용량 | GB 단위 | MB 단위 |
| OS | 각자 별도 OS | Host OS 공유 |
| 격리 수준 | 완전 격리 | 프로세스 격리 |

## 4. Dockerfile 구조

```dockerfile
# 1. 베이스 이미지 선택 (어떤 OS/환경 위에서 시작할지)
FROM node:18-alpine

# 2. 작업 디렉토리 설정
WORKDIR /app

# 3. 파일 복사 (로컬 → 컨테이너)
COPY package*.json ./

# 4. 명령어 실행 (패키지 설치)
RUN npm install

# 5. 나머지 소스코드 복사
COPY . .

# 6. 컨테이너가 사용할 포트 명시
EXPOSE 3000

# 7. 컨테이너 시작 시 실행할 명령어
CMD ["node", "app.js"]
```

> `COPY package*.json ./` 을 소스코드 복사보다 먼저 하는 이유가 있음. Docker는 레이어 캐시를 활용해서 빌드 속도를 높이는데, 패키지가 바뀌지 않으면 `npm install` 을 다시 안 해도 됨. 이 순서 지키는 것만으로도 빌드 시간이 확 줄어듦.

## 5. docker-compose

여러 컨테이너를 **한 번에 관리**하는 도구

```
내 프로젝트
├── Backend 컨테이너 (Spring / Node.js)
├── Frontend 컨테이너 (React)
├── DB 컨테이너 (MySQL / PostgreSQL)
└── Nginx 컨테이너 (리버스 프록시)
```

이걸 일일이 `docker run` 으로 띄우면 너무 복잡함
`docker-compose.yml` 하나로 전부 정의하고 명령어 한 줄로 올림

```yaml
# docker-compose.yml 예시
version: '3.8'

services:
  backend:
    build: ./backend       # Dockerfile 위치
    ports:
      - "8080:8080"        # 호스트:컨테이너 포트 매핑
    environment:
      - DB_HOST=database   # 환경변수
    depends_on:
      - database           # database 먼저 실행

  database:
    image: mysql:8.0       # Docker Hub에서 이미지 가져옴
    environment:
      - MYSQL_ROOT_PASSWORD=secret
      - MYSQL_DATABASE=mydb
    volumes:
      - db-data:/var/lib/mysql  # 데이터 영속성 보장

volumes:
  db-data:
```

```bash
docker-compose up -d    # 전체 실행 (백그라운드)
docker-compose down     # 전체 종료
docker-compose logs -f  # 전체 로그 확인
```

> `depends_on`은 컨테이너 시작 순서만 보장하고, DB가 완전히 준비됐는지는 보장 안 함. DB 연결 에러가 나면 이게 원인일 수 있음! `healthcheck` 옵션을 같이 쓰면 해결

## 6. Docker Hub

Docker 이미지를 저장하고 공유하는 **클라우드 저장소** (Github의 이미지 버전)

```
Docker Hub = 이미지들의 Github
```

```bash
docker pull mysql:8.0        # Docker Hub에서 이미지 다운로드
docker push my-app:latest    # Docker Hub에 이미지 업로드
```

> Gitlab CI/CD 파이프라인에서 빌드한 이미지를 **Gitlab Container Registry**에 저장 가능. Docker Hub 대신 Gitlab 자체 저장소를 쓰는 것임. lab.ssafy.com도 지원하니까 나중에 파이프라인 구성할 때 활용해봐도 좋을 듯

## Docker 이론 정리

```
Docker 핵심 이론
├── Image      ← 설계도 (읽기 전용)
├── Container  ← 실행 인스턴스 (Image로 찍어냄)
├── Dockerfile ← Image 만드는 레시피
├── docker-compose ← 여러 컨테이너 한번에 관리
└── Docker Hub ← 이미지 저장소 (Gitlab Registry도 가능)
```
